01

OS

DOCKER DESKTOP
약 5GB 디스크

인터넷
초기 다운로드용

"Docker", "컨테이너", "이미지" 같은 단어가 낯설어도 전혀 문제없습니다. 이 가이드는 그 단어들을 모르고도 끝까지 진행할 수 있도록 만들어졌어요. 스크립트가 자동으로 다 해줍니다.

02

Docker Desktop 설치

5~10분 · 한 번만 하면 끝
⊞
Windows 10/11
DESKTOP · 64-BIT

아래 링크에서 인스톨러를 받아 더블클릭으로 설치 → PC 재부팅 → 트레이의 작은 고래 아이콘이 멈출 때까지 30초~1분 대기.

  • docker.com/products/docker-desktop 접속 → "Download for Windows"
  • 설치 도중 "Use WSL 2" 옵션이 보이면 체크해두기
  • 재부팅 후 시작 메뉴에서 "Docker Desktop" 실행
⌘
macOS
INTEL · APPLE SILICON

본인 Mac의 칩(Intel 또는 Apple Silicon)에 맞는 dmg를 받아 Applications로 드래그.

  • docker.com/products/docker-desktop 접속 → "Download for Mac"
  • Apple Silicon(M1/M2/M3/M4)이면 "Apple chip" 버전 선택
  • Applications에서 Docker 실행 → 첫 실행 시 helper 권한 다이얼로그 동의
03

서버 파일 받기

2분 · git GUI로 한 번에
1

git GUI 도구를 설치해요

코드 한 줄 안 쓰고 클릭으로만 받기 위해, 다음 중 편한 걸 하나 설치해주세요. 둘 다 무료입니다.

  • 🪟🍎 GitHub Desktop — 가장 간단, 한글 메뉴
  • 🪟🍎 Fork — 다른 화면을 보고 싶다면
2

아래 주소로 deploy 브랜치를 받아요

GUI 도구의 "Clone repository" 메뉴를 열고, 아래 주소와 브랜치를 입력해 본인 PC 원하는 위치(예: 바탕화면 또는 문서 폴더)에 받습니다.

# Repository URL https://github.com/snoowood/stone_server.git # Branch (반드시 deploy 선택!) deploy

GitHub Desktop의 경우: File → Clone repository → URL 탭 → 위 주소 붙여넣기 → Local path 선택 → 받은 뒤 Current branch 메뉴에서 deploy로 전환.

3

받은 폴더 안에 이런 파일들이 있어요

받은 폴더를 탐색기/Finder로 열면 다음과 같이 보입니다. 어떤 파일을 더블클릭할지만 기억하면 돼요.

📁 stone_server/ ← 받은 폴더 (위치는 본인이 정한 곳) ├── 📁 _internal/ (자동 처리 — 건드릴 일 없음) ├── 📁 nginx/ (자동 처리) ├── 📄 .env.template (자동 생성용 — 건드릴 일 없음) ├── 📄 docker-compose.tester.yml (자동 처리) ├── 📄 README.md (영어 문서) │ ├── ▶️ start.bat Windows · 서버 켜기 (제일 자주 씀) ├── ▶️ start.command Mac · 서버 켜기 ├── ⏹️ stop.bat / stop.command 서버 끄기 ├── 📜 logs.bat / logs.command 로그 보기 └── ♻️ update.bat / update.command 최신 받기
04

서버 켜기

처음 1~2분 · 이후 10초
1

본인 OS에 맞는 시작 파일을 더블클릭

Windows: start.bat 더블클릭
Mac: start.command를 우클릭 → 열기 (첫 실행만 이렇게, 이후엔 더블클릭 OK)

⚠ 처음 한 번은 보안 경고가 떠요 — 정상이에요
Windows는 "Windows에서 PC를 보호했습니다" 화면이 떠요 → 추가 정보 → 실행 클릭.
Mac은 "확인되지 않은 개발자" 경고 → 우클릭 → 열기로 한 번만 허용하면 그 다음부턴 안 뜹니다.
2

창에서 일어나는 일들 (그냥 기다리면 됨)

검은 창에서 다음 일들이 순서대로 자동 진행돼요. 첫 실행은 약 1~2분, 이후엔 10초 정도면 끝납니다.

  • ① Docker Desktop이 꺼져 있으면 자동 실행 (고래 아이콘 깨우기)
  • ② 첫 실행이면 보안 키(.env)를 본인 PC용으로 자동 생성
  • ③ 서버 이미지를 인터넷에서 받아옴 (≈ 15MB)
  • ④ 서버, 데이터베이스, 캐시 컨테이너 4개를 동시에 켬
  • ⑤ 서버가 응답할 때까지 잠깐 대기 → 준비 완료 메시지!
3

이 메시지가 뜨면 성공! 🎉

창에 아래와 비슷한 출력이 보이면 서버가 정상 가동 중입니다.

start.bat
[init] Docker is ready.
[pull] Fetching the latest server image...
[up] Starting services...
[wait] Waiting for the server to become healthy...
 
=== Server ready ===
Health check : https://localhost:8443/api/v1/health
Client URL : https://localhost:8443
 
Use stop.bat to shut down, logs.bat to view logs.
4

이 창은 그대로 두세요

서버는 이 검은 창이 떠 있는 동안 계속 동작합니다. 창을 닫지 말고 다음 단계(클라이언트 실행)로 넘어가요. 다 끝나면 그때 끄면 됩니다.

05

클라이언트 실행

1분 · 인게임 진입
1

개발팀에게 받은 Unity 클라이언트 빌드 실행

사내 드라이브 또는 메신저로 전달받은 Unity 클라이언트 빌드(.exe 또는 .app)를 더블클릭으로 실행합니다.

전달받은 위치를 모르거나 빌드가 없다면 개발팀(gensdeis)에게 요청해주세요.

2

자동으로 본인 PC 서버에 접속

테스트용 클라이언트 빌드는 https://localhost:8443에 자동으로 붙도록 만들어져 있습니다. 별도 IP/포트 입력 불필요.

🌐 다른 PC에서 접속하고 싶다면

같은 사무실 네트워크의 다른 PC에서 본인 서버에 붙고 싶다면 .env 파일을 메모장으로 열어 LAN_BIND=0.0.0.0으로 바꾼 뒤 stop → start. 자세한 건 개발팀에 문의해 주세요.

3

인게임 진입 → 캐릭터/리소스 확인

로그인 후 확인하고 싶은 캐릭터/맵/이펙트로 이동해 원화/모델/애니메이션이 의도대로 보이는지 확인합니다.

로그인은 "테스트 UUID" 방식이라 같은 UUID로 다시 들어오면 같은 캐릭터로 로그인됩니다 — 빌드가 알아서 처리합니다.

06

끄기 · 로그 · 업데이트

필요할 때만 · 더블클릭
⏹️

서버 끄기

stop.bat / stop.command

작업 마치면 더블클릭. 데이터(캐릭터 진행 등)는 그대로 남아 있어서 다음에 켜면 이어서 시작합니다.

📜

로그 확인

logs.bat / logs.command

뭔가 이상할 때 더블클릭하면 최근 200줄의 서버 로그가 보입니다. 이 내용을 개발팀에 전달해주시면 빠르게 도와드릴 수 있어요.

♻️

최신 버전 받기

update.bat / update.command

"서버에 새 변경이 있어요" 라는 안내를 받았을 때 더블클릭. 자동으로 최신 파일 + 이미지로 갱신 후 다시 시작합니다.

07

문제가 생기면

대부분 여기서 해결
Docker Desktop을 종료(트레이 우클릭 → Quit Docker Desktop)했다가 다시 실행해보세요. 그래도 안 되면 PC를 재부팅하면 거의 모든 경우 해결됩니다. Windows라면 BIOS의 가상화(VT-x / SVM) 옵션이 꺼져 있을 수도 있어요 — 이 경우 개발팀에 문의해 주세요.
macOS의 Gatekeeper가 첫 실행을 막은 거예요. 우클릭 → 열기를 한 번만 해주시면 그 다음부턴 더블클릭으로 잘 됩니다. "확인되지 않은 개발자" 경고가 떠도 열기를 눌러 진행하면 됩니다.
정상입니다. 본인 PC용 자체 서명 인증서를 사용 중이라서 그래요. Unity 클라이언트는 테스트 모드에서 이 경고를 자동으로 무시하도록 만들어져 있습니다. 브라우저로 직접 health check를 열어보고 싶다면 "고급 → 안전하지 않음으로 계속"을 눌러 진행하시면 됩니다.
다른 프로그램이 8080 또는 8443 포트를 이미 쓰고 있다는 뜻이에요. 받은 폴더 안의 .env 파일을 메모장으로 열고 HTTP_PORT=18080, HTTPS_PORT=18443 같은 다른 숫자로 바꾼 뒤 stop → start. 클라이언트 접속 주소도 같은 포트로 자동 맞춰집니다.
서버 컨테이너 안에서 뭔가 꼬인 경우입니다. logs.bat 또는 logs.command를 더블클릭해서 나오는 출력을 통째로 복사해 개발팀(gensdeis)에 전달해주세요. 화면을 캡쳐해 보내주셔도 좋아요.
stop.bat 또는 stop.command로 끄신 뒤, 받은 폴더 안의 .env 파일만 삭제해주세요. 다음 start에서 새 보안 키로 다시 생성됩니다. 그래도 이상하면 폴더를 통째로 지우고 03번 단계부터 다시 받아도 OK입니다.
logs.bat/logs.command를 한 번 돌려서 나오는 출력을 캡쳐하고, "이런 동작을 했더니 이런 메시지가 떴어요"라고 개발팀(gensdeis)에 알려주세요. 무엇을 클릭했는지 / 어떤 화면이 떴는지 시간 순서대로 적어주시면 진단이 훨씬 빨라요.
