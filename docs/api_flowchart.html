Stone Server — Client / Server API Flow

HTTP REST · Gin · JWT(RSA) + Refresh Token · SQLite/Postgres + KV(InMem/Redis)

1 최초 접속 & 로그인 (Steam 인증)

클라이언트가 Steam ticket으로 인증을 요청하면 서버가 JWT와 refresh_token을 발급한다.

flowchart TD A[클라이언트 시작] --> B[Steam SDK로
auth ticket 획득] B --> C["POST /api/v1/auth/steam
body: ticket"] C --> D{RateLimiter} D -- 초과 --> D1[429 Too Many Requests] D -- 통과 --> E{ticket SHA256
1회용 claim} E -- 이미 사용 --> E1[409 TICKET_USED] E -- claim OK --> F[Steam API
AuthenticateTicket] F -- 무효 --> F1[401 INVALID_TICKET] F -- steam_id 획득 --> G[DB upsertPlayer
player_states init
login streak 갱신] G --> H[JWT 발급 jti=uuid] H --> I{enforceSingleSession
session:jti 등록} I -- 충돌 --> I1[409 LOGIN_IN_PROGRESS] I -- OK --> J[refresh_token 저장
KV] J --> K["200 OK { jwt, refresh_token, expires_at }"] K --> L[클라이언트 토큰 보관]

2 보호된 API 호출 (예: 클릭 전송)

JWT 서명 검증 → 세션 라이브 체크 → RateLimit → 비즈니스 로직.

flowchart TD A[클라이언트] -->|Authorization: Bearer JWT| B["POST /api/v1/player/clicks"] B --> C{JWTAuth middleware} C -- Bearer 없음 --> C1[401 UNAUTHORIZED] C -- RSA pubKey 검증 --> D{서명/만료 OK?} D -- 실패 --> D1[401 invalid or expired] D -- OK --> E{KV 조회 session:jti} E -- 없음 --> E1[401 session revoked] E -- 존재 --> F{RateLimiter} F -- 초과 --> F1[429] F -- 통과 --> G[playerHandler.PostClicks
비즈니스 로직 실행] G --> H[DB 업데이트] H --> I[200 OK + 결과]
동일 패턴이 적용되는 라우트: /player/state /gacha/pull /gacha/status /gacha/logs /achievement/unlock /achievement/list

3 JWT 만료 → Refresh

Refresh Token으로 새 JWT를 발급받는다. Per-player 락과 쿨다운으로 동시 갱신을 방지.

flowchart TD A[API 호출 401 expired 수신] --> B["POST /api/v1/auth/refresh
body: refresh_token"] B --> C{lookupRefreshToken KV} C -- 없음 --> C1[401 INVALID_REFRESH_TOKEN] C -- player_id 확인 --> D{acquireRefreshLock
per-player} D -- 락 실패 --> D1[409 REFRESH_IN_PROGRESS] D -- 락 획득 --> E{cooldown 중?} E -- yes --> E1[409 REFRESH_IN_PROGRESS] E -- no --> F{stored token == 요청 token?} F -- 다름 --> F1[401 REFRESH_TOKEN_REVOKED
새 로그인으로 무효화됨] F -- 일치 --> G[새 JWT 발급 새 jti] G --> H[enforceSingleSession] H --> I[refresh cooldown 설정] I --> J[새 refresh_token 저장
이전 lookup 무효화] J --> K["200 OK { new_jwt, new_refresh_token }"] K --> L[클라이언트 토큰 교체
원 API 재시도]

4 로그아웃

서명만 검증하고 세션을 폐기한다 (이미 revoke된 토큰도 로그아웃 가능).

서명만 검증} C -- 실패 --> C1[401] C -- OK --> D[authHandler.AuthLogout] D --> E[KV에서
session:jti 삭제
refresh_token 삭제] E --> F[200 OK] F --> G[클라이언트 토큰 폐기]

5 부팅 직후 — Public 호출 (헬스체크 / 시간 동기화)

로그인 전에 호출 가능한 무인증 엔드포인트. 시간 동기화로 클라 타임가드 기준을 맞춤.

flowchart TD A[클라이언트 부팅] --> B["GET /api/v1/health"] B --> C[DB ping + KV ping] C --> D[200 OK / 503] A --> E["POST /api/v1/time/sync"] E --> F[서버 UTC 반환] F --> G[클라이언트 시간 보정
타임가드 기준] G --> H[시나리오 1로 진행]

6 전체 라이프사이클 요약

부팅 → 인증 → 플레이 루프 → 만료시 갱신 → 로그아웃.

flowchart LR Boot[부팅] --> Health[/health] Health --> TimeSync[/time/sync] TimeSync --> Login[/auth/steam] Login --> Play{게임 플레이} Play -->|JWT 유효| API[보호 API 호출] API --> Play Play -->|JWT 만료| Refresh[/auth/refresh] Refresh --> Play Play -->|종료| Logout[/auth/logout]

★ 핵심 정리

  • 인증 모델: Steam ticket → JWT(RSA, 단기) + Refresh Token(KV 장기)
  • 싱글 세션: session:jti 키로 한 계정 1세션 강제
  • 방어 장치: ticket 1회용 claim · refresh per-player lock + cooldown · RateLimiter
  • 저장소 분기: SQLITE_PATH 유무에 따라 SQLite+InMem 또는 Postgres+Redis
  • 통신: 전부 HTTP/1.1 REST (소켓/WebSocket 미사용)
