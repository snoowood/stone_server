## 총평

문서의 목표, 예산, 기술 스택, 운영 범위는 한눈에 이해되며 초기 기획서로서 완성도가 높다. 다만 현재 워크스페이스에는 구현 코드가 없어 디렉토리 구조와 성능 수치는 "검증 완료"가 아니라 "가정 기반 목표치"로 보는 것이 맞다.

## 확인된 강점

- 시스템 범위가 인증, 가챠, 시간 검증, 저장, 업적으로 명확히 분리되어 있다.
- 단일 Lightsail + Docker Compose 조합은 초기 라이브 운영 비용 제약과 잘 맞는다.
- PostgreSQL, Redis, Nginx, Go 조합은 요구사항 대비 과하지 않고 운영 복잡도도 낮다.

## 보완 필요 사항

1. Steam 인증 티켓 흐름 표기가 수정되어야 한다.
현재 개요도에는 `GetAuthSessionTicket()` 기준으로 적혀 있으나, Steam의 `AuthenticateUserTicket` Web API와 맞는 클라이언트 호출은 `GetAuthTicketForWebApi()` 쪽이 더 직접적이고 공식 가이드와도 일치한다.

2. "JWT는 Stateless"와 "Redis session 저장"의 운영 모델이 문서들 사이에서 충돌한다.
완전 Stateless JWT인지, Redis 검증이 들어가는 하이브리드 세션인지 하나로 고정해야 이후 인증 미들웨어와 로그아웃 정책이 흔들리지 않는다.

3. 예상 처리 용량은 근거 문구가 추가되어야 한다.
`500 CCU`, `200 RPS`는 좋은 목표치지만 부하 테스트 또는 동시성 모델 근거가 아직 없으므로 "초기 추정치"라고 표기하는 편이 안전하다.

4. 단일 호스트 구조의 리스크가 명시되어야 한다.
현재 구조는 비용 면에서 적절하지만 DB, Redis, 앱이 모두 한 호스트에 있어 장애 시 전체 중단된다. 이 리스크를 받아들이는 운영 전략이라는 점과 백업/복구 기준을 함께 적는 편이 좋다.

5. "서버 권위" 원칙과 API 설계가 일부 충돌한다.
후속 문서의 `PATCH /player/state`는 클라이언트가 delta를 보내는 구조라 잘못 구현하면 서버 권위가 약해진다. 개요 차원에서도 "상태 변경은 가능한 한 서버 도메인 이벤트 기반" 원칙을 명시하는 편이 맞다.

## 권장 수정

- Steam 인증 관련 호출명을 `GetAuthTicketForWebApi()` 기준으로 통일
- 인증 모델을 `Stateless JWT` 또는 `Redis 검증 포함 하이브리드 세션` 중 하나로 명시
- 예상 성능 수치에 "가정 기반" 표시 추가
- 단일 호스트 장애 수용 방침과 백업/복구 기준 한 줄 추가

## 2차 검토 (`v2.0`, 2026-05-03)

### 반영 확인

- `GetAuthTicketForWebApi()` 기준으로 인증 흐름이 수정되었다.
- 인증 모델이 `JWT + Redis jti` 하이브리드 세션으로 명확해졌다.
- 서버 권위 원칙이 별도 섹션으로 승격되어 후속 문서 기준점 역할을 하게 되었다.
- 단일 호스트 리스크와 RTO/RPO가 명시되었다.
- 성능 수치가 "초기 추정치"로 정리되어 과도한 확정 표현이 사라졌다.

### 잔여 확인 사항

1. 개요 수준에서는 큰 구조 충돌이 대부분 해소되었다.
현재 남은 쟁점은 개요 문서 자체보다 하위 설계 문서의 세부 규칙 정합성에 가깝다.

2. 다중 기기 정책은 최종적으로 한 줄 더 못 박아두면 좋다.
하이브리드 세션 구조는 잘 잡혔지만, "여러 기기 동시 로그인 허용 여부"는 이후 Redis 키 설계와 refresh token 정책에 직접 영향을 준다.

### 2차 판정

개요 문서는 **승인 가능 수준**이다. 이후 수정은 하위 문서의 구현 세부 설계 보강 위주로 진행하면 된다.

## 3차 검토 (`v3.0`, 2026-05-03)

### 반영 확인

- 단일 활성 세션 정책이 명시되어 다중 기기 관련 해석 여지가 사라졌다.
- refresh token을 플레이어당 1개 유지한다는 정책도 개요 수준에서 확정되었다.

### 잔여 확인 사항

개요 문서 기준으로는 더 이상 구조적 충돌이 보이지 않는다. 남은 사항은 구현 세부 설계와 경계 조건 처리 문제다.

### 3차 판정

개요 문서는 **확정 가능 수준**이다.
